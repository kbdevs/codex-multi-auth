# v2.1.13-kb.0

Local fork release for restoring native Codex ChatGPT auth behavior in wrapper-launched sessions.

## Wrapper Runtime

### Fixes

- Wrapper-launched Codex request commands now use persistent selected-account native Codex homes by default instead of the localhost Responses proxy.
- `codexRuntimeRotationProxy` now defaults to `false`; set it to `true`, run `codex-multi-auth rotation enable`, or set `CODEX_MULTI_AUTH_RUNTIME_ROTATION_PROXY=1` to opt into the legacy proxy path.
- Native per-account homes are written under `~/.codex/multi-auth/native-homes/` and keep `auth.json`, `accounts.json`, and `config.toml` isolated per selected account.
- Stale `codex-multi-auth-runtime-proxy` provider config is stripped from generated native homes so normal ChatGPT auth is used.

## Install Behavior

### Fixes

- Postinstall self-heal no longer assumes runtime rotation is active when config helpers are unavailable.
- The app-server shim uses a shell launcher on POSIX instead of copying the Node binary, avoiding dynamic-library startup failures on macOS.

## Release Hygiene

### Tests

- Added native-home generation coverage.
- Added wrapper coverage proving default launches do not start the runtime proxy and explicit proxy opt-in still works.
- Added PATH splitter coverage for Windows drive-letter paths on POSIX test hosts.
